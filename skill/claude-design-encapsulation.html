I

产品本质：一句话定义

Claude Design 是 Anthropic 于 2026.04.17 发布的 AI 设计工具，驱动模型为 Claude Opus 4.7（视觉模型）。核心能力：用户用自然语言描述想法，即可生成设计稿、原型和幻灯片。

核心创新：将 DESIGN.md 从纯粹的设计文档规范，升级为 AI 可执行的技能定义。这是设计系统第一次真正拥有了"可执行的形态"。

II

核心抽象：DESIGN.md 格式

2.1 九层文档结构

DESIGN.md 不是普通的设计规范文档。它是专为 LLM 阅读理解优化的结构化技能定义：

层级内容LLM 视角
1. Visual Theme & Atmosphere视觉主题与氛围整体基调
2. Color Palette & Roles色彩方案与语义角色语义绑定
3. Typography Rules字体排版规范刻度精确
4. Component Stylings组件样式定义原子单元
5. Layout Principles页面布局原则空间规则
6. Depth & Elevation阴影/层次表现纵深系统
7. Do's and Don'ts设计禁则硬性红线
8. Responsive Behavior响应式适配逻辑多端兼容
9. Agent Prompt GuideAI 代理专用提示词执行入口

2.2 五条关键设计原则

AI 优先

格式专为 LLM 阅读理解优化，非设计师视角——这是给机器执行的设计文档

语义绑定

颜色值绑定功能角色，如：--primary: #0057FF /* 信任蓝 */

像素级细节

字间距微调至极致，杀死 AI 乱配色的可能性

几何倍数网格

强制使用 4px/8px 几何倍数间距系统

硬性审美红线

设立类似"绝不许用纯白"的硬性规则，不可绕过

2.3 颜色语义绑定示例

## 2. Color Palette & Roles
- Primary: #0057FF (信任蓝 - 用于 CTA 按钮)
- Secondary: #1A1A2E (深邃黑 - 用于正文)
- Accent: #FF6B35 (活力橙 - 用于强调)
- Background: #FAFBFC (极浅灰 - 用于底色)

## 3. Typography Rules
- 主字体: Inter, -apple-system, sans-serif
- 标题: 700 weight, 1.2 line-height
- 正文: 400 weight, 1.6 line-height
- 字间距: -0.01em (视觉微调)

关键洞察：传统设计令牌是"值 + 描述"，DESIGN.md 的令牌是"值 + 语义 + 执行意图"。AI 不仅知道颜色是什么，还知道用在什么地方和为什么用它。

V

与普通 Coding Agent 的差异

核心差异：一句话
普通 Agent 是"画家"——每次创作风格随机。
DESIGN.md + Agent 是"熟练工"——严格按设计规范执行，风格精确一致。

┌─────────────────────────────────────────────────────────┐
│              普通 Coding Agent (如 baseline)              │
├─────────────────────────────────────────────────────────┤
│  用户: "帮我做一个登录页面"                                 │
│  AI:   自由发挥，每次风格可能不同                           │
│  结果: 千篇一律的灰色界面 + 默认 Tailwind 样式类             │
│  问题: 颜色/间距/字体全靠随机，品质不可控                    │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼  DESIGN.md 约束注入
┌─────────────────────────────────────────────────────────┐
│          DESIGN.md + Coding Agent (VoltAgent 模式)        │
├─────────────────────────────────────────────────────────┤
│  用户: "帮我做一个登录页面"                                 │
│  AI:   读取 DESIGN.md → 遵循 Mint Fresh 风格               │
│  结果: 精准的品牌色、4px 间距系统、Inter 字体                │
│  优势: 像熟练工而非随机生成                                  │
└─────────────────────────────────────────────────────────┘
能力维度普通 Coding AgentDESIGN.md + Agent
风格一致性每次不同精确一致
颜色控制随机或偏好语义绑定
间距系统随意几何倍数强制
组件边界模糊堆积明确规则
约束机制无硬性审美红线

这是一个典型的技能封装（Skill Encapsulation）模式：

  • DESIGN.md = 技能的定义层（What & Why）
  • SKILL.md = 技能的执行层（When & How）
  • 设计资源 = 技能的资产层（Assets & Components）
  • LLM 输出 = 技能的执行结果（Generated Output）

对 ip-website-generator 的参考价值

7.1 当前问题

用户请求 → Agent 自由生成 → 每次风格随机
         ↑
    缺少一致的设计约束层

│                                                         │
└─────────────────────────────────────────────────────────┘

7.3 具体建议方向

建立风格库

参考 awesome-claude-design，发布预置 DESIGN.md 文件包

技能化封装

将 DESIGN.md + 生成规则封装为 Hermes Skill

双重文件

参照 Claude Design 双轨制 (README.md + SKILL.md)

约束下沉

在生成 prompt 中嵌入硬性设计规则，强制不可绕过

7.4 实施路径

  1. Phase 1: 整理 3-5 个示范性 DESIGN.md（个人 IP 风格包）
  2. Phase 2: 封装为 ip-website-generator 的 skill
  3. Phase 3: 在生成 prompt 中引用 DESIGN.md 约束
  4. Phase 4: 输出时附「风格预览」确认步骤
